# Handoff: редизайн IvaMaris TDO (модуль DCC)

## Обзор

Редизайн веб-интерфейса системы технического документооборота IvaMaris TDO
(репозиторий `valroi/iva_tdo`, ветка `main`). Цель — привести интерфейс к фирменному
стилю «ИваМарис» и снизить операционные издержки пользователей: меньше кликов до
результата, читаемые таблицы, понятная навигация, явная зависимость доступных
действий от роли и статуса ревизии.

Функционал не меняется. Все экраны воспроизводят существующие сущности и процессы
ядра DCC: MDR → ревизии (A/B/00, цели IFR/AFD) → очередь ТРМ → рассмотрение
заказчиком → замечания и CRS → коды AP/AN/CO/RJ.

## О файлах в этом пакете

Файл `IvaMaris TDO Redesign.dc.html` — **дизайн-референс, сделанный в HTML**. Это
прототип, показывающий предполагаемый внешний вид и поведение, а **не production-код
для копирования**. Задача разработчика — воспроизвести эти экраны в существующей
среде проекта (React 19 + TypeScript + Vite + Ant Design 5), используя уже принятые
в кодовой базе паттерны: компоненты antd (`Layout`, `Menu`, `Table`, `Card`, `Tag`,
`Segmented`), утилиты `utils/datetime.ts`, `utils/pagination.ts`,
`utils/revisionActions.ts`, `utils/revisionProcess.ts`, `utils/revisionHints.ts`.

Прототип открывается в браузере; переключение экранов — по левому меню, а также через
панель Tweaks (свойство `startScreen`).

## Точность (fidelity)

**High-fidelity.** Цвета, типографика, отступы и радиусы заданы окончательно и
приведены ниже в разделе «Дизайн-токены». Верстку следует воспроизводить точно,
но средствами antd + собственного CSS, а не переносом инлайновых стилей прототипа.

## Порядок внедрения и откат

Рекомендуемый порядок (от низкого риска к высокому):

1. **Тема и токены** — `ConfigProvider theme` + `frontend/src/styles.css`. Затрагивает
   всё приложение, но не логику. Отдельный коммит.
2. **Оболочка** — сайдбар, переключатель модулей, шапка (`App.tsx`). Без изменения
   `Section`/`parseHash`.
3. **Таблицы и карточки** — плотность, колонки, раскрытие ревизий (`DashboardPage`,
   `DocumentsRegistryPage`, `TrmRegistryPage`).
4. **Действия по ролям** — `utils/revisionActions.ts` и карточка ревизии. Наиболее
   рискованный пункт: логика прав уже выверена, менять только представление
   (показ/скрытие и подсказки), не саму матрицу прав. Обязателен прогон `pytest`
   и ручная проверка под ролями через `?profile=`.

Точка отката: работать в ветке `feature/redesign-brand`, перед выкладкой поставить
тег на текущем коммите `main` (например `pre-redesign`), деплой сначала на тестовый
контур, на прод — после проверки под всеми ролями.

## Экраны

Общая оболочка (все экраны, кроме входа): сайдбар 260px слева, шапка 52px сверху
(sticky), рабочая область с отступами 20px 24px 44px. Минимальная ширина рабочей
области 1320px — при более узком окне прокручивается вся оболочка целиком, колонки
не сжимаются.

### 1. Вход

Двухколоночный экран: левая часть — графит `#383E42`, логотип, заголовок 36px/1.14,
подзаголовок; правая колонка 452px на белом — поля Email и Пароль (высота 42px,
радиус 9px, рамка `#E1E3E3`, фокус — рамка бирюзовая + кольцо), основная кнопка
44px, ссылка «Саморегистрация», пояснение про гостевой портал подрядчика по
ссылке-приглашению.

### 2. Обзор (`DashboardPage`)

- Ряд из 4 карточек-счётчиков: «Документы», «Уведомления», «Задачи по замечаниям»,
  «Просроченные документы». Значение 30px/800, кликабельны (переход в реестр,
  уведомления, CRS). Просрочка и непрочитанные — красным.
- Блок «Приближается выпуск ≤ 7 дней»: колонки Проект / Документ / Название /
  Плановый выпуск / Осталось. Осталось — пилюля: серая, янтарная (≤2 дн), красная
  (просрочено). Показывается только при праве `can_create_mdr`.
- Таблица «Текущие задачи»: колонки Задача (заголовок события + текст сообщения
  моноширинным), Создана, Проект, Роль, Дедлайн, От кого, кнопка «Открыть».
  Источник — непрочитанные уведомления + очередь рассмотрения заказчика.
- Блок «Профиль и роли в проектах»: ФИО, Email, сторона; таблица проект → назначение
  (в т.ч. «LR по дисциплине EL»).

### 3. Проекты (`ProjectsPage`)

- Левая колонка 380px: дерево проект → категории (PD/SE) → дисциплины, с счётчиками
  документов; клик ведёт в реестр с преднастроенным фильтром.
- Правая: карточка «Участники проекта» (аватар-инициалы, ФИО, роль, сторона) и
  карточка «Матрица рассмотрения» (Дисциплина / LR / R) с пояснением, что назначение
  в матрице выдаёт права автоматически.

### 4. Документы и ревизии (`DocumentsRegistryPage`)

- Панель фильтров: Проект, Категория, Дисциплина, Название, Статус выпуска
  (AP/AN/CO/RJ), Шаг воркфлоу, По замечаниям, Просрочка + кнопка «Применить фильтр».
  Справа — переключатель плотности строк (Свободно 11px / Плотно 8px по вертикали)
  и «Выгрузка».
- Секции по категориям (PD — «Проектная документация», SE — «Инженерные изыскания»)
  с тегом кода и счётчиком.
- Колонки: раскрытие, Проект, Дисциплина, Документ (моноширинный, бирюзовый, ссылка),
  Название, Рев., Статус ревизии (точка-индикатор + текст), Код (AP/AN/CO/RJ, пилюля),
  Автор, Замечания (открытые/всего — янтарная пилюля при открытых, зелёная при нуле).
- Раскрытая строка: вложенная таблица ревизий — Рев / Цель / Статус / По замечаниям /
  ТРМ (ссылка на реестр ТРМ) / Автор / «Открыть».

### 5. Карточка документа (`RevisionCardPage`)

- Шапка: шифр, статус-пилюля, ревизия и цель выпуска, номер ТРМ (ссылка), заголовок 19px.
- Полоса этапов процесса (6 шагов): Ревизия создана → Загружен PDF → Отправлено в ТРМ →
  Рассмотрение заказчика → CRS подрядчику → Закрытие 00/AFD. Пройденные — зелёная
  полоска, текущий — бирюзовая, будущие — серые, под каждым — дата.
- Полоса метаданных из 4 ячеек: Проект, Дисциплина, Автор ревизии, Дедлайн
  рассмотрения (просрочка — красным).
- Вкладки: Замечания / Ревизии / Файлы / История.
- Список замечаний: код в квадрате (цвет по коду), автор, время, лист, состояние
  («внутреннее» / «в CRS-00007»), текст, счётчик вложений.
- Правая колонка (sticky): панель действий, «История ревизий», «Файлы ревизии»
  с кнопкой «Открыть PDF».

**Панель действий — ключевой элемент.** Набор кнопок зависит от роли и статуса
ревизии; недоступные действия не скрываются, а показываются приглушёнными с
пояснением «Недоступно: …». Внизу — строка «мяч у кого».

| Роль | Ожидает решения ТДО | На рассмотрении | Замечания отправлены |
|---|---|---|---|
| Рук. ТДО подрядчика | Отправить в ТРМ (осн.), Отклонить выпуск, Заменить PDF | Открыть ТРМ, Скачать PDF, «Отправить в ТРМ» — недоступно (уже отправлено, повтор не перевыдаёт номер) | Назначить исполнителя (осн.), Скачать CRS, «Ответить» — недоступно (отвечает автор ревизии) |
| Разработчик | Заменить PDF (осн.), Скачать PDF, «Отправить в ТРМ» — недоступно (отправляет рук. ТДО) | Скачать PDF, «Создать следующую ревизию» — после CRS, «Ответить» — замечания не опубликованы | Ответить «A» (осн.), Ответить «I», Загрузить новую ревизию |
| LR заказчика | Открыть PDF, «Добавить замечание» — ревизия не передана, «Отправить CRS» — нет ревизии на рассмотрении | Отправить CRS (осн.), Добавить замечание, Поставить AP | «Ожидать ответ подрядчика», Открыть CRS, «Отозвать CRS» — недоступно |

Матрица прав в проде — `utils/revisionActions.ts` + права
`can_upload_files`, `can_raise_comments`, `can_publish_comments`,
`can_process_tdo_queue`. Новое здесь только представление: причина недоступности.

### 6. PDF-просмотрщик (`RevisionPdfAnnotator`)

Тулбар: «← К карточке», зум −/значение/+ (50–400%, Ctrl+колесо), «Лист N из M»,
кнопки «+ Замечание» и «↧ PDF с замечаниями». Полотно листа с соотношением 1:1.414
на сером фоне `#ECEEEE`, тень `0 2px 10px rgba(56,62,66,.12)`. Рамки замечаний —
2px, цвет по коду, номер в круге 22px в левом верхнем углу рамки. Правая панель —
список замечаний текущего листа с кодом, автором и текстом, внизу напоминание, что
замечания внутренние до отправки CRS.

Важно: координаты замечаний хранятся в пикселях рендера шириной 780px
(`BASE_PAGE_WIDTH` / `_ANNOTATOR_RENDER_WIDTH`) — базу менять нельзя, иначе «уедут»
все существующие замечания.

### 7. Очередь ТРМ (`TdoQueuePage`)

Подсказка сверху с номером следующего транcмиттала. Таблица с чекбоксами: Проект,
Документ, Название, Рев., Цель, Загружено, действия «В ТРМ» / «Отклонить» / «PDF».
Внизу — счётчик выбранного и кнопка «Отправить пакетом в ТРМ» (графитовая).

### 8. Формирование CRS (`CrsPage`)

Слева — список внутренних замечаний с чекбоксами (код, шифр, текст, автор), справа
(sticky) — карточка пакета: номер CRS, отправитель, получатель, срок ответа и кнопка
«Отправить CRS · N замечаний» с пояснением о переходе ревизии в «Замечания отправлены».
Ниже — печатный **лист замечаний CRS** (см. ниже).

### 9. Реестр ТРМ (`TrmRegistryPage`)

Раскрывающиеся пакеты: номер, дата, число документов, направление (SHP → IVA),
состояние, кнопка «Сопроводительный лист». Внутри — таблица № / Шифр / Название /
Рев. / Цель / Статус / Код. Ниже — печатный **сопроводительный лист**.

### 10. Печатные листы (ТРМ и CRS)

Формат «бумажного» документа шириной до 940px: шапка с логотипом и названием листа,
номер справа, двойная линия-разделитель графитом; блок реквизитов в 3 колонки
(номер, проект, отправитель/получатель, дата, количество, ответственный/срок ответа);
таблица позиций; для ТРМ — две линии подписи «Передал / Принял»; кнопки «↧ Скачать
XLSX» и «Печать».

Бэкенд уже отдаёт `GET /trm/{trm_number}/transmittal.xlsx` — формат колонок
совпадает: № / Шифр / Название / Ревизия / Цель выпуска / Статус / Код замечаний.

### 11. Уведомления (`NotificationsPage`)

Фильтры-пилюли «Непрочитанные» (активная — графит) / «Все» и кнопка «Отметить все
прочитанными». Строки: цветная точка по типу события, заголовок события, текст
моноширинным, пилюля «новое/прочитано», время, кнопка «Открыть». Прочитанные — на
фоне `#FAFBFB`.

### 12. Отчётность (`ReportingPage`)

Четыре показателя (выпущено ревизий, средний срок рассмотрения, документы с AP,
просрочено), блок «Готовность по дисциплинам» (прогресс-полосы с примечаниями) и
таблица «Прогресс документов» — шифр, текущий этап, прогресс-полоса со значением,
код. Ступени прогресса соответствуют захардкоженным в бэкенде: 70 / 75 / 80 / 85 /
90 / 100%.

## Взаимодействия и поведение

- Навигация: разделы переключаются как сейчас — состояние `activeSection` + hash
  (`#/revision_card/42`). Новых секций не добавляется, кроме отдельного экрана
  просмотрщика (в проде это модалка — сохранить модалку, макет показывает содержимое).
- Раскрытие строк реестра и пакетов ТРМ — локальное состояние, без перезапроса.
- Ховеры: строки таблиц — фон `#FAFBFB`; вторичные кнопки — рамка `#C6CBCB`;
  основная кнопка — затемнение бирюзового до `oklch(0.43 0.095 190)`.
- Пилюли статусов и кодов не кликабельны.
- Переключатель плотности реестра сохранять в localStorage (как `paginationProps`).
- Переключатель роли в шапке макета — **демонстрационный**, в проде роль берётся
  из профиля пользователя и матрицы рассмотрения. Не переносить.

## Состояние

Дополнительного состояния относительно текущего кода почти не требуется:
- `density: 'default' | 'compact'` для реестра (localStorage);
- локальные `expandedRowKeys` для реестра и реестра ТРМ;
- выбор строк (`selectedRowKeys`) в очереди ТРМ и в CRS — для пакетных действий;
- причины недоступности действий — вычисляются из уже существующей матрицы прав.

## Чего не делать

- Не менять матрицу прав и статусную машину ревизий — только представление.
