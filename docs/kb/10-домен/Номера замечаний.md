# Номера замечаний

Маска: **`{ПРОЕКТ}-RMK-000123`** (напр. `IMP-RMK-000042`) — сквозная по проекту,
6 разрядов (~1 млн замечаний на проект).

- Поле `Comment.remark_number`, присваивается **при создании** родительского
  замечания (`_next_remark_number`, max+1 по префиксу проекта) и **не меняется
  никогда** — carry-over на следующую ревизию сохраняет исходный номер, поэтому
  по номеру видно всю цепочку.
- Ответы-реплики (`parent_id != NULL`) своего номера не получают — они часть
  истории родительского замечания.
- Замечания, созданные до внедрения нумерации, пронумерованы идемпотентным
  бэкфиллом при старте (`services/remark_numbers.backfill_remark_numbers`,
  порядок по `created_at`).

## Где виден номер

Карточка документа (колонка «№ замечания», моно, копируется), Excel-выгрузка
замечаний, карточка замечания, поиск в шапке приложения.

## Карточка замечания

`GET /remarks/{remark_number}` → `RemarkCardRead`: реквизиты (документ, ревизия,
лист, код, статус, CRS) + **история** (`RemarkHistoryEvent`):

| kind | Что означает |
|---|---|
| `CREATED` | замечание создано (ревизия, лист, автор, текст) |
| `CRS_SENT` | передано подрядчику (номер CRS) |
| `CONTRACTOR_REPLY` | ответ подрядчика (A — принято, I — не согласен) |
| `LR_DECISION` | решение LR: снято/отклонено/скорректировано/закрыто |
| `CARRY_OVER` | проверка на следующей ревизии (устранено / не устранено) |

Фронт: `pages/RemarkCardPage.tsx`, секция `remark_card`, URL `#/remark_card/IMP-RMK-000123`,
поиск по номеру — в шапке (`App.tsx`). Подрядчику карточка отдаётся только для
опубликованных замечаний ([[CRS и передача замечаний]]).
