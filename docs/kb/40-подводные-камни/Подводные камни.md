# Подводные камни

Реальные грабли, на которые уже наступали. Читать перед правкой смежного кода.

## Данные и совместимость

- **Координаты замечаний привязаны к рендеру 780px.** Менять `BASE_PAGE_WIDTH` /
  `_ANNOTATOR_RENDER_WIDTH` нельзя — уедут все существующие замечания ([[Замечания и PDF]]).
- **Автомиграции только добавляют колонки.** Переименование поля = потеря данных ([[Бэкенд]]).
- **Новая таблица со ссылкой на revisions/comments/documents ⇒ дописать зачистку в
  `_purge_mdr_tree`** (`routers/mdr.py`). Иначе Postgres отбивает удаление документа
  `ForeignKeyViolation`, а в UI это выглядит как «кнопка не работает». Так выстрелили
  сначала `document_attachments`/`carry_over_decisions`/`notifications`, потом
  `review_events`/`revision_reviewer_states`/`comment_attachments` (2026-08-31).
  Вложенные MDR удаляются каскадом вместе с родителем — их `parent_id` тоже FK.
- **Время naive-UTC.** Бэкенд пишет `datetime.utcnow()` без tz; фронт трактует как UTC и
  показывает в МСК. Не «чинить» добавлением +3 на бэке — сместится дважды.
- **Одна логика в двух местах:** эффективный код замечаний считается и на фронте
  (`revisionProcess.ts`), и на бэке (`_latest_effective_review_code`). Менять синхронно.

## Права и видимость

- Фильтр «подрядчик видит только опубликованное» живёт в **нескольких** выдачах
  (`list_comments`, `get_revision_card`). Добавляя новую выдачу замечаний — не забыть фильтр
  ([[CRS и передача замечаний]]).
- `parent_id` в payload обязателен там, где фронт фильтрует родительские замечания:
  без него `undefined !== null` и список молча пустеет (баг реестра, 2026-08-04).
- Наблюдатель не должен попадать в очереди задач, но должен видеть данные ([[Роли и права]]).

## Браузеры и UI

- **Старые Chrome (<119)**: нужен `polyfills.ts`, иначе PDF роняет весь интерфейс
  («Ошибка интерфейса» = ErrorBoundary).
- **React делает `onWheel` пассивным** — для Ctrl+зума вешать нативный слушатель с `passive:false`.
- **Chrome не рисует кириллицу во всплывающих заметках PDF** ([[Кириллица в PDF]]).
- **Сканы в JPEG 2000 (`/JPXDecode`) без `openjpeg.wasm` рисуются пустыми.** pdf.js
  декодирует JPX только через WASM-модуль; при его отсутствии страница выходит
  белой (видно лишь векторные элементы, напр. подпись), а в скачанном файле всё
  на месте. Ассеты кладёт `frontend/scripts/copy-pdfjs-assets.mjs` (predev/prebuild)
  в `public/pdfjs/`, пути передаются через `wasmUrl`/`cMapUrl`/`standardFontDataUrl`
  в `RevisionPdfAnnotator`. Апгрейд `pdfjs-dist` — проверить, что скрипт скопировал
  все три каталога.

## Формы и JSON-колонки

- **История правок MDR пишется в JSON-колонку** `mdr_records.dates`. Класть туда
  «сырые» `date`/`datetime`/Enum нельзя — SQLAlchemy падает на сериализации
  (`Object of type date is not JSON serializable`), PUT отдаёт 500. Значения
  приводить через `_jsonable` (`routers/mdr.py`).
- **`form.validateFields()` бросает исключение.** Если вызвать его вне
  try/catch, кнопка «ОК» молча ничего не делает — пользователь не понимает,
  что не так. Ловить, показывать сообщение и `form.scrollToField` к первому
  проблемному полю.
- **Легаси-записи могут не иметь обязательных полей** (напр. пустой
  `serial_number` у документов старой схемы шифра). В режиме редактирования
  такие поля не требовать — иначе запись невозможно отредактировать вообще.
